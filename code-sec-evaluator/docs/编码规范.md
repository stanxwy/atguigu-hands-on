## 1. 总体原则

| 原则 | 说明 |
| --- | --- |
| 可读性优先 | 代码是给人读的，其次才是给机器执行；宁写长一点也不要晦涩 |
| 一致性 | 全仓库统一风格，杜绝"个人风格"，以本规范与自动化工具为准 |
| 最小惊讶 | 命名、行为、边界符合直觉，不搞"黑魔法" |
| 单一职责 | 一个函数/组件只做一件事，逻辑过深即拆分 |
| 显式优于隐式 | Python 侧遵循 `Explicit is better than implicit`；TS 侧避免隐式 any |
| 不重复造轮子 | 优先复用标准库/成熟三方库（本项目已定型的依赖清单见 SPEC §5.1） |

## 2. 代码风格统一

### 2.1 Python 侧风格标准

**基准：PEP 8 + Black（代码格式化）+ isort（import 排序）+ Ruff（静态检查，替代 Flake8）。**

| 维度 | 规范 | 说明 |
| --- | --- | --- |
| 缩进 | 4 个空格，**禁止 Tab** | 不用制表符，混用即 CI 失败 |
| 行宽 | 88 字符（Black 默认） | 文档字符串/长 URL 可豁免 |
| 引号 | **双引号** `"..."`（Black 默认） | 字符串内部含双引号时用单引号 |
| 尾随逗号 | 多行结构末尾加尾随逗号 | 便于 diff 与增删行 |
| 括号位置 | 函数/类/方法左括号不换行，参数多时括号内换行 | 由 Black 统一 |
| 空行 | 顶层定义间 2 行，类内方法间 1 行 | 遵循 PEP 8 |
| 空格 | 运算符两侧、逗号后、`=`/`:` 参数默认值周围加空格；紧贴括号内侧不加空格 | 由 Black 统一 |
| 行尾空白 | **禁止** | 由 pre-commit 清除 |
| 文件末尾 | 以单个换行符结束 | 由 pre-commit 保证 |
| 编码声明 | 统一 UTF-8（Python 3 默认），无需 `# -*- coding -*-` | — |
| 类型注解 | 所有公开函数/方法必须有完整类型注解 | 见 §5.1 |

#### 正反例（格式）

```python
# 正例（Black 格式化后）
def build_report(
    project_id: int,
    report_markdown: str,
    report_html: str,
    *,
    report_file_path: str | None = None,
) -> Report:
    """生成并持久化项目安全评估报告。"""
    ...


# 反例：行宽超限、缩进 2 空格、缺尾随逗号、单引号
def build_report(project_id: int, report_markdown: str, report_html: str):
    report = Report(project_id=project_id, report_markdown=report_markdown,
      report_html=report_html)
    return report
```

#### 强制工具链（后端）

| 工具 | 用途 | 建议版本 | 关键配置要点 |
| --- | --- | --- | --- |
| Black | 代码格式化 | 24.x | `line-length = 88`；`target-version = ["py311"]` |
| isort | import 排序 | 5.x | `profile = "black"`；`line_length = 88`；与 Black 兼容 |
| Ruff | 静态检查/可选格式化 | 0.8.x | 启用 `E`/`F`/`W`/`I`/`UP`/`B` 规则集；`line-length = 88` |

`backend/pyproject.toml` 建议配置：

```toml
[tool.black]
line-length = 88
target-version = ["py311"]

[tool.isort]
profile = "black"
line_length = 88

[tool.ruff]
line-length = 88
target-version = "py311"

[tool.ruff.lint]
select = ["E", "F", "W", "I", "UP", "B", "N"]
ignore = ["E501"]  # 行宽交给 Black 处理
```

> **依赖管理（uv）**：后端依赖统一用 **uv** 管理，不再使用 `pip install -r requirements.txt`。上述 `[tool.black]`/`[tool.isort]`/`[tool.ruff]` 片段与 `[project]`、`[dependency-groups]` 共存于同一个 `backend/pyproject.toml`（完整结构见 SPEC §5.1）。安装命令：
>
> ```bash
> cd backend
> uv sync      # 自动创建 .venv，安装 dependencies + [dependency-groups].dev（含 black/isort/ruff/pytest 等）
> uv lock      # （可选）重新解析并锁定版本，生成/更新 uv.lock
> ```
>
> `uv.lock` 为锁定版本的权威来源，由 `uv lock`/`uv sync` 生成并提交仓库。

### 2.2 TypeScript/React 侧风格标准

**基准：Prettier（格式化）+ ESLint（静态检查）。**

| 维度 | 规范 | 说明 |
| --- | --- | --- |
| 缩进 | 2 个空格 | 禁止 Tab |
| 行宽 | 100 字符（`printWidth: 100`） | 由 Prettier 自动折行 |
| 引号 | **单引号** `'...'` | JSX 属性统一双引号（Prettier 默认） |
| 分号 | 语句末尾**必须加分号** | Prettier `semi: true` |
| 尾随逗号 | 多行对象/数组/参数末尾加尾随逗号 | Prettier `trailingComma: "all"` |
| 箭头函数括号 | 单参数省略圆括号，多参数/无参数保留 | `x => x`；`(a, b) => a + b` |
| JSX 括号 | JSX 属性统一双引号；多行 JSX 用圆括号包裹 | `<Component title="报告" />` |
| 换行规则 | 每行一个语句；大括号不另起一行（K&R 风格） | 由 Prettier 统一 |
| 空行 | 顶层声明间保留空行；import 与代码间空一行 | ESLint `padding-line-between-statements` |
| 行尾空白 | **禁止** | 由 Prettier 清除 |

#### 正反例（格式）

```tsx
// 正例
export function ProjectDetail({ projectId }: ProjectDetailProps) {
  const { project, fetchProject } = useProjectStore();

  useEffect(() => {
    fetchProject(projectId);
  }, [projectId, fetchProject]);

  return <ProjectPanel project={project} />;
}

// 反例：无分号、双引号、缩进 4 空格、缺尾随逗号
export function ProjectDetail({ projectId }: ProjectDetailProps) {
    const { project, fetchProject } = useProjectStore()
    useEffect(() => {
        fetchProject(projectId)
    }, [projectId, fetchProject])
    return <ProjectPanel project={project} />
}
```

## 3. 命名规则

### 3.1 通用原则

| 原则 | 说明 |
| --- | --- |
| 语义清晰 | 名称即文档，看到名字就知道"是什么/做什么" |
| 避免缩写滥用 | 除业界公认缩写（`id`、`url`、`api`、`http`、`db`、`ws`、`cpu`、`mem`）外禁用自造缩写 |
| 避免歧义 | 不用 `data`、`info`、`tmp`、`result` 这类泛化词做唯一标识，除非作用域极短 |
| 长度适中 | 2~4 个单词为佳；宁可长一点也不可失去语义 |
| 布尔值 | 用 `is_`/`has_`/`can_`（Python）或 `is`/`has`/`can`（TS）前缀命名 |
| 集合 | 复数或 `_list`/`_map` 后缀表达数量（如 `vulnerabilities`、`stage_map`） |

### 3.2 Python 命名约定

| 对象 | 约定 | 示例 |
| --- | --- | --- |
| 变量/函数/方法 | `snake_case` | `project_status`、`get_vulnerability()` |
| 类 | `PascalCase` | `ProjectService`、`Scheduler` |
| 常量 | `UPPER_SNAKE_CASE` | `DEFAULT_TIMEOUT_SECONDS`、`RISK_LEVELS` |
| 私有成员 | 单下划线前缀 `_` | `_validate_source_path()`、`self._cache` |
| 模块/文件 | `snake_case` 小写 | `project_service.py`、`isolation_service.py` |
| 包/目录 | 小写单词，无下划线 | `services`、`schemas`、`models` |
| 类型变量 | 单大写字母或 `T` 前缀 | `T`、`TModel` |
| 异常类 | `PascalCase` + `Error` 后缀 | `IsolationError`、`NotFoundError` |

> 特殊约定：`__init__.py` 内不写业务逻辑，仅做重导出（`__all__`）。

### 3.3 TypeScript/React 命名约定

| 对象 | 约定 | 示例 |
| --- | --- | --- |
| 变量/函数 | `camelCase` | `projectStatus`、`getVulnerability()` |
| 组件/接口/类型/枚举 | `PascalCase` | `ProjectList`、`ProjectDetailProps` |
| 常量 | `UPPER_SNAKE_CASE` 或 `camelCase`（详见下） | `DEFAULT_TIMEOUT_SECONDS` |
| Hook | `useXxx` 前缀 | `useProjectStore`、`useWebSocket` |
| 组件文件 | `.tsx`，`PascalCase` 文件名 | `ProjectList.tsx`、`Monitor.tsx` |
| 普通模块/工具文件 | `.ts`，`camelCase` 文件名 | `apiClient.ts`、`format.ts` |
| 类型声明文件 | `.d.ts` | `global.d.ts`、`vite-env.d.ts` |
| 私有/内部成员 | 无强制 `_`（TS 用 `private` 修饰） | `private client: AxiosInstance` |
| 未使用参数 | `_` 前缀 | `(_event, data) => {}` |
| Zustand store | `useXxxStore` 命名（hook 形式） | `useProjectStore`、`useAuthStore` |

> **枚举/联合类型常量约定**：与后端枚举（`risk_level`、`verify_status`、`message_type` 等）对齐时，TS 侧用 `as const` 定义 + 联合类型导出，值保持 snake_case 字符串（与数据库/接口一致），名称用 PascalCase 常量。

```ts
// 正例：与后端枚举值对齐，值用 snake_case，类型用联合
export const RISK_LEVELS = ['critical', 'high', 'medium', 'low'] as const;
export type RiskLevel = (typeof RISK_LEVELS)[number];
```

### 3.4 正反例对照

| 场景 | 正例 | 反例 | 说明 |
| --- | --- | --- | --- |
| 项目状态 | `project_status` / `projectStatus` | `pst`、`status` | 避免缩写与泛化 |
| 漏洞列表 | `vulnerabilities` | `vlist`、`vul` | 复数表达集合 |
| 是否只读挂载 | `is_mount_readonly` / `isMountReadonly` | `readonly`、`ro` | 布尔前缀清晰 |
| 最大并发数 | `max_concurrency` / `maxConcurrency` | `mc`、`concurrencyNum` | 语义完整 |
| 攻击路径明细 | `attack_path_items` / `attackPathItems` | `items`、`api` | 保留领域上下文 |
| 复现步骤 | `reproduce_steps_text` / `reproduceStepsText` | `steps`、`rs` | 与表字段对齐 |
| 用户映射 | `user_map` / `userMap` | `map`、`m` | 明确键值类型 |
| 临时变量（短作用域） | `i`、`idx`、`ch` | `aaaa`、`data1` | 循环内可短，其余不行 |

## 4. 注释要求

### 4.1 注释总原则

| 原则 | 说明 |
| --- | --- |
| 解释"为什么" | 注释应说明意图、约束、非显而易见的决策，而非复述"做什么" |
| 代码即文档 | 命名清晰时无需逐行注释；优先把复杂逻辑抽象成具名函数 |
| 同步更新 | 修改代码必须同步更新注释/文档字符串，**禁止过期注释** |
| 注释语言 | 统一中文（团队语境），术语与枚举值保留英文原文 |
| 位置 | 行内注释用 `# `（Python）/ `// `（TS）后留一个空格 |

### 4.2 Python docstring

**采用 Google 风格。**

- 所有**公开模块、类、方法、函数**必须有 docstring。
- 复杂内部函数（>10 行或含分支逻辑）也建议补充。
- 内容包含：一句话概述（Summary）、Args、Returns、Raises（如适用）。

```python
def start_project(self, project_id: int) -> Project:
    """启动指定项目的评估任务。

    将项目状态置为 running，创建 5 个阶段记录，并通过信号量
    控制并发，随后由后台调度器异步推进阶段状态机。

    Args:
        project_id: 待启动的项目 ID。

    Returns:
        更新后的 Project 模型实例（状态为 running）。

    Raises:
        NotFoundError: 项目不存在。
        StatusConflictError: 项目当前状态不允许启动（非 created/completed/failed/stopped）。
    """
    ...
```

### 4.3 TypeScript JSDoc

**采用 JSDoc，`@param`/`@returns`/`@throws` 标注。**

- 导出函数、公共组件、工具函数必须有 JSDoc。
- 组件建议描述职责与主要 props 含义（复杂 props 用 interface 字段注释承载）。

```ts
/**
 * 启动项目评估任务。
 *
 * @param projectId 待启动的项目 ID。
 * @returns 启动后的项目状态快照。
 * @throws 当项目状态不允许启动时抛出 2002 业务错误。
 */
export async function startProject(projectId: number): Promise<ProjectStatus> {
  ...
}
```

### 4.4 行内注释规范

| 场景 | 要求 |
| --- | --- |
| 复杂算法/正则 | 简述思路或分步骤说明 |
| 非显而易见的魔法值 | 说明取值依据（如超时、并发上限） |
| 规避某个 bug/坑 | 说明原因与链接（issue 号） |
| 业务规则映射 | 标注对应 PRD/SPEC 条目（如 `# 见 SPEC §2.4 级联删除`） |
| 空分支/占位 | 必须写清楚为何留空 |

```python
# 正例
# 容器销毁失败不阻塞事务回滚，仅记录告警（见 SPEC §2.4 删除项目事务）
if not destroy_container(container_id):
    logger.warning("销毁容器失败，跳过文件清理告警: %s", container_id)

# 反例（复述代码，无信息量）
project.status = "running"  # 设置状态为 running
```

### 4.5 TODO / FIXME 标记规范

| 标记 | 用途 | 格式要求 |
| --- | --- | --- |
| `TODO` | 计划内、尚未实现的后续工作 | `TODO(<作者>/<编号>): 描述` |
| `FIXME` | 已知缺陷/临时补丁，需尽快修复 | `FIXME(<作者>/<编号>): 描述 + 影响` |
| `HACK` | 临时绕过/非常规写法 | `HACK(<作者>): 原因` |
| `XXX` | 可疑代码，需复核 | `XXX(<作者>): 疑问` |

```python
# TODO(kou/JIRA-42): 支持 git_repo 的私有凭据鉴权（当前仅支持 HTTPS 公开仓库）
# FIXME(kou/JIRA-18): 超大报告 LONGTEXT 存在截断风险，需评估分片存储
```

> **约束**：`TODO`/`FIXME` 必须附作者与编号（issue/ticket 号），且进入迭代收尾前须被清理或转为正式任务。CI 可配置 `fixme` 类规则统计，阻止数量增长。

### 4.6 禁止过期注释

- 每次修改函数行为、参数、返回结构时，**必须**同步修改 docstring/JSDoc 与相关行内注释。
- Code Review 关注点：注释与代码不一致视为**缺陷**，等同逻辑错误。
- 工具侧可用 ESLint `eslint-plugin-jsdoc` 校验 JSDoc 一致性；Python 侧用 Ruff `D`（pydocstyle）规则做最低约束。

## 5. Python 后端专项规范

### 5.1 类型注解与 Pydantic v2

| 要点 | 规范 |
| --- | --- |
| 类型注解 | 所有公开函数签名带注解；返回类型必须显式，禁止仅写 `-> None` 缺参数注解 |
| 现代写法 | 用 `list[str]`、`dict[str, int]`、`str \| None`（3.11 起），禁用 `typing.List/Optional` |
| Pydantic 模型 | 继承 `BaseModel`，字段用类型注解声明，必填/可选明确 |
| Schema 命名 | 请求 `XxxCreate`/`XxxUpdate`，响应 `XxxOut`/`XxxDetail`（与 SPEC §4 `schemas/` 对应） |
| 校验 | 用 `Field(..., ge=, le=, max_length=)` 声明约束，禁止在接口内手写散乱校验 |
| Config | `model_config = ConfigDict(from_attributes=True)` 支持 ORM 序列化 |

```python
from pydantic import BaseModel, ConfigDict, Field

class ProjectCreate(BaseModel):
    """创建项目请求体。"""

    project_name: str = Field(..., min_length=1, max_length=128)
    source_type: Literal["local_path", "git_repo"]
    source_path: str = Field(..., max_length=512)
    task_content: str | None = None

class ProjectOut(BaseModel):
    """项目响应体（ORM 序列化）。"""

    model_config = ConfigDict(from_attributes=True)

    id: int
    project_name: str
    source_type: str
    source_path: str
    project_status: str
    created_at: datetime
```

### 5.2 SQLAlchemy 2.0 模型

| 要点 | 规范 |
| --- | --- |
| 声明方式 | 用 `Mapped[...]` + `mapped_column`（2.0 语义），禁止旧式 `Column` |
| Base | 统一继承 `Base`（`database.py` 提供），模型一个文件一张表 |
| 主键 | `Mapped[int] = mapped_column(primary_key=True, autoincrement=True)` |
| 时间字段 | 用 `DateTime(timezone=True)`，UTC 存储 |
| 关系 | 用 `relationship()` 声明，级联策略与 SPEC §2.4 严格对齐 |
| 枚举 | 以 `str` 存储 + 应用层常量约束（SPEC §2.1），不在模型层用数据库枚举 |
| 命名 | 模型类与表结构对齐：`Project`、`RuntimeStage`、`Vulnerability` |

```python
class Vulnerability(Base):
    """漏洞表模型（对应 SPEC §2.2.5）。"""

    __tablename__ = "vulnerabilities"

    id: Mapped[int] = mapped_column(BigInteger, primary_key=True, autoincrement=True)
    project_id: Mapped[int] = mapped_column(
        ForeignKey("projects.id", ondelete="CASCADE"), index=True
    )
    vuln_code: Mapped[str] = mapped_column(String(64))
    vuln_title: Mapped[str] = mapped_column(String(255))
    risk_level: Mapped[str] = mapped_column(String(16), index=True)
    verify_status: Mapped[str] = mapped_column(String(16), default="unverified")
    created_at: Mapped[datetime] = mapped_column(DateTime(timezone=True), server_default=func.now())
```

### 5.3 分层与职责边界

| 层 | 职责 | 禁止事项 |
| --- | --- | --- |
| `api/` | 参数校验、鉴权、调用 service、组装响应 | 写业务逻辑、直接操作 ORM 增删改查 |
| `services/` | 业务核心（调度/隔离/角色/报告/监控） | 解析 HTTP 请求、直接返回 Response |
| `models/` | 表结构映射 | 写业务方法（保持纯映射） |
| `schemas/` | Pydantic 请求/响应模型 | 混入 ORM 逻辑 |
| `core/` | 横切能力（安全/错误码/常量） | 依赖业务 service |
| `utils/` | 纯函数工具（文件/编号/白名单） | 依赖数据库 session |

### 5.4 异步与并发

| 要点 | 规范 |
| --- | --- |
| 阻塞 IO | 命令执行、Docker SDK、文件 IO 等阻塞操作丢入 `ThreadPoolExecutor`（`asyncio.to_thread` 或 `run_in_executor`），禁止在事件循环内同步阻塞 |
| 并发控制 | 用 `asyncio.Semaphore` 限制 `task.max_concurrency`，不要自造轮子 |
| 异常 | 异步任务内必须捕获异常并落库/推送，避免静默失败 |
| 资源 | 数据库 session、容器句柄、文件句柄均需 `with`/`try-finally` 保证释放 |

```python
import asyncio

async def run_scan_command(command: str) -> str:
    """在隔离容器内执行只读命令（阻塞 IO 移出事件循环）。"""
    return await asyncio.to_thread(_exec_docker_command, command)
```

## 6. TypeScript/React 前端专项规范

### 6.1 组件与文件结构

| 要点 | 规范 |
| --- | --- |
| 组件类型 | 函数组件 + hooks，禁止 class 组件 |
| 导出方式 | 组件默认导出或具名导出二选一并在项目内统一（建议具名导出） |

### 6.2 状态管理（Zustand）

| 要点 | 规范 |
| --- | --- |
| Store 命名 | `useXxxStore`（hook 形式），文件放 `store/` |
| Store 拆分 | `auth`、`project`、`ws` 独立 store，单一职责 |
| 异步动作 | 在 store action 内处理 loading/error 状态，页面不散落请求逻辑 |
| 选择器 | 用细粒度 selector 订阅，避免整包订阅导致多余渲染 |
| WebSocket | 连接生命周期（建立/重连/关闭）集中在 `useWebSocket` hook 或 `ws` store 管理 |

```ts
interface ProjectState {
  project: ProjectDetail | null;
  status: 'idle' | 'loading' | 'error';
  error: string | null;
  fetchProject: (id: number) => Promise<void>;
  reset: () => void;
}

export const useProjectStore = create<ProjectState>((set) => ({
  project: null,
  status: 'idle',
  error: null,
  fetchProject: async (id) => {
    set({ status: 'loading', error: null });
    try {
      const project = await projectApi.getDetail(id);
      set({ project, status: 'idle' });
    } catch (e) {
      set({ status: 'error', error: formatApiError(e) });
    }
  },
  reset: () => set({ project: null, status: 'idle', error: null }),
}));
```

### 6.3 类型安全

| 要点 | 规范 |
| --- | --- |
| 禁止 `any` | 除确需（极少数第三方库边界）外禁止 `any`，用 `unknown` 收窄 |
| 接口对齐 | `types/` 下类型与后端 Pydantic schema 字段一一对应 |
| 联合类型 | 枚举/状态用 `as const` + 联合类型（见 §3.3），与后端枚举值一致 |
| 非空断言 | 禁止 `!` 非空断言，改用可选链 + 空值守卫 |
| 严格模式 | `tsconfig.json` 开启 `"strict": true`、`"noImplicitAny": true` |

```ts
// 正例：类型守卫收窄
function isRiskLevel(value: string): value is RiskLevel {
  return RISK_LEVELS.includes(value as RiskLevel);
}

// 反例：any 与断言滥用
function parse(msg: any) {
  const vuln = msg.data!; // 禁止
  return vuln.title;
}
```
