# 知识库管理平台（KBMS）产品需求文档（PRD）

> **TL;DR**：本平台是一个集「知识维护、多维权限管理、AI 鉴权问答、数据看板、知识自动沉淀」于一体的知识库管理系统。核心闭环是：知识管理员导入文档 → 系统拆分出「知识单元」并按「全局/部门/角色/个人」四维数据权限授控 → 提问者登录后经 AI 检索召回、鉴权过滤后获得有权限的流式答案 → 高频未命中问题自动沉淀为 FAQ 候选与知识缺口，经审核发布后反哺知识库。本文档为唯一事实源（Single Source of Truth），供架构师据此编写 SPEC。

**一句话描述**：知识库管理平台是一套面向企业/组织的智能知识管理系统，支持单篇与批量知识导入、细粒度数据权限控制、AI 鉴权检索问答、数据看板统计，以及 FAQ 与知识缺口的自动沉淀闭环。

## 4. 用户故事与验收标准

> 每条用户故事采用「作为…，我希望…，以便…」格式；每项验收标准标注对应的 2.9.11 验收条目（AC-1 ~ AC-8，详见附录 D）。

### 4.1 认证与权限

**US-1（对应 F1）**
> 作为**系统管理员/知识管理员/普通用户**，我希望能够用账号密码登录并获取自身角色权限，以便安全进入系统、看到与自己权限匹配的菜单与功能。

- 验收标准：
  - 未登录访问任何受保护接口/页面，返回 `401` 并跳转登录页。
  - 登录成功后签发 Token，`GET /api/auth/me` 正确返回用户、角色、部门信息。（AC-1）
  - 不同角色登录后，仅能看到被授权的菜单与操作按钮（增删改查、AI 访问等）。
  - 连续多次密码错误触发限流/锁定策略（可配置）。

### 4.2 组织架构与权限管理

**US-2（对应 F2/F3/F4）**
> 作为**系统管理员**，我希望能够创建/维护用户、角色、部门，并分配菜单与操作权限，以便实现对平台访问的细粒度管控。

- 验收标准：
  - 用户支持增删改查；角色可关联多用户；部门呈树形层级。（AC-1）
  - 角色可配置「菜单可见性 + 操作权限（增/删/改/查/AI 访问）」；保存后即时生效。
  - 删除角色/部门时，若有用户关联需给出提示或级联处理策略。
  - 权限变更后，对应用户下次请求即按新权限执行鉴权。

### 4.3 知识维护与导入

**US-3（对应 F5/F6）**
> 作为**知识管理员**，我希望单篇/批量上传文档后系统自动拆分为知识单元，以便快速把内容沉淀为可检索的知识。

- 验收标准：
  - 单个文件上传后，解析并生成 1 个知识单元（唯一标识），内容正确切分。（AC-2）
  - 批量上传支持多文件，展示导入进度与成功/失败明细；失败可重试。
  - 默认支持 PDF / Word / Markdown / TXT，可扩展 Excel / HTML / 图片 OCR（格式清单见附录 E）。
  - 导入后的知识单元**默认无任何访问权限**，直至显式配置。（AC-3）

**US-4（对应 F7/F8）**
> 作为**知识管理员**，我希望对知识单元进行增删改查并管理状态，以便保证知识内容的准确性与时效性。

- 验收标准：
  - 知识单元列表支持按标题/状态/创建时间/权限范围筛选与分页。（AC-2）
  - 编辑保存即覆盖原内容，不保留历史版本（见附录 E · 已确认决策）。
  - 状态支持「草稿 / 已发布 / 已下线」，仅「已发布」参与检索召回。
  - 删除为软删除（或需二次确认），不影响已产生的问答日志（问答日志保留 180 天）。

### 4.4 数据权限配置

**US-5（对应 F9）**
> 作为**知识管理员**，我希望为每个知识单元配置「全局/部门/角色/个人」四维数据权限，以便精确控制谁能检索和查看该内容。

- 验收标准：
  - 四类权限实体：`global / department / role / user`，支持多实体混合配置。（AC-3）
  - 多实体之间为 **OR** 关系：命中任意一种即视为可访问。
  - 「部门」权限递归包含其子部门成员（见附录 E · 已确认决策）。
  - 未配置任何权限的知识单元，任何提问者（含知识管理员）均不可检索。
  - 权限配置界面支持按实体类型搜索并勾选目标（部门树/角色列表/用户列表）。

### 4.5 AI 鉴权问答

**US-6（对应 F10/F11）**
> 作为**提问者**，我希望登录后以自然语言提问并得到答案，以便在数据权限边界内高效获取知识。

- 验收标准：
  - 问答前强制校验登录态；未登录返回 `401`，前端引导登录。（AC-4）
  - 检索召回后，调用鉴权接口过滤，**仅拼装当前用户有权限的知识单元内容**生成答案。
  - 对无权限的召回项，明确给出「权限缺失」友好提示（如「部分内容因权限不足未展示，共 N 条」），不泄露内容本身。（AC-4）

**US-7（对应 F12/F13）**
> 作为**提问者**，我希望回答以流式输出并附带引用来源，且能查看历史会话，以便验证答案可信度并延续多轮对话。

- 验收标准：
  - 回答采用 SSE 流式返回，首字延迟达标（见 5.1 性能）。
  - 答案附引用来源列表（知识单元标题 + 可跳转链接）。
  - 会话支持新建/列表/历史详情，历史问答可回溯。（AC-4）

### 4.6 数据看板

**US-8（对应 F14/F15/F20）**
> 作为**系统管理员/知识管理员**，我希望通过看板查看访问量、知识总量、FAQ 排行、高频知识排行、Token 消耗与响应时间，以便评估平台运营与 AI 成本。

- 验收标准：
  - 看板展示：访问量/访问人数、知识单元总量、常见问题排行、高频访问知识单元排行、Token 消耗、响应时间统计。（AC-5）
  - 指标口径与 `qa_access_logs` 每轮问答日志一一对应，可下钻/按时间范围筛选。
  - Token 消耗区分输入（prompt）/输出（completion）分别统计；响应时间统计口径为服务端处理耗时（不含流式传输耗时）；二者支持按日聚合趋势展示。（见附录 E · 已确认决策）

### 4.7 知识沉淀

**US-9（对应 F16/F17/F21）**
> 作为**知识管理员**，我希望系统自动推荐高频候选 FAQ 并审核发布，以便将反复提问沉淀为标准化答案、降低人工成本。

- 验收标准：
  - 系统对相似问题进行**语义去重**（相似度 ≥ 0.85），达到**频次阈值**（≥ 3）后自动生成候选 FAQ 推荐；阈值放配置文件（env 可覆盖 + 代码默认值）。（AC-6）
  - 候选 FAQ 经管理员审核通过后状态置为 `published`，并写入缓存加速后续检索。（AC-6）
  - 已发布 FAQ 库支持检索与分类；候选/已发布可分别筛选。

**US-10（对应 F18）**
> 作为**知识管理员**，我希望识别「召回相似度低于阈值」或「无知识支撑」的未命中问题并聚合展示，以便定位知识空白、指导补录。

- 验收标准：
  - 知识缺口 = 召回相似度 < 0.5 或 无知识单元支撑 的提问，按频次聚合；阈值放配置文件（env 可覆盖 + 代码默认值）。（AC-6）
  - 缺口列表展示问题文本、相似度、频次、最近出现时间，可一键「转为知识导入任务」。

## 5. 非功能需求

### 5.1 性能

| 指标 | 目标值 |
|---|---|
| 常规页面/列表接口 P95 响应 | ≤ 500ms |
| AI 问答首字延迟（TTFT） | ≤ 2s（P95） |
| AI 问答完整回答时长 | 流式输出，无阻塞 |
| 并发问答 | 支撑 ≥ 50 并发会话 |
| 知识导入 | 单篇 ≤ 10s；批量任务异步化，不阻塞 UI |
| 数据权限鉴权 | 单次召回过滤 ≤ 100ms |

> 注：看板「响应时间」统计口径为服务端处理耗时（不含流式传输耗时）。

### 5.2 安全

- 所有接口（除登录）强制鉴权；敏感接口（权限配置、用户管理）需操作权限校验。
- 密码加密存储（加盐哈希），禁止明文落盘/日志。
- Token 设置过期时间并支持刷新；登出后 Token 失效。
- 数据权限鉴权必须在**服务端**完成，前端仅做展示，防止越权绕过。
- 无权限召回内容**不得**以任何形式（含日志、异常堆栈、网络报文）泄露正文。
- 关键操作（导入、发布、权限变更）记录审计日志。

### 5.3 兼容性

- 浏览器：Chrome / Edge / Safari / Firefox 最近两个大版本。
- 响应式：桌面端为主，管理后台分辨率 ≥ 1280px；问答工作台适配常见平板宽度。
- 文件格式：PDF、Word（.docx）、Markdown（.md）、TXT（可扩展，见附录 E）。
- 部署：支持 Docker Compose 一键启动（前后端 + 数据库 + 中间件）。

## 附录 C · 核心业务流程（3 条）

### C1. 知识批量维护与权限配置

```
知识管理员 → 登录 → 导入中心 → 单篇/批量上传
  → 系统解析拆分 → 生成知识单元（默认无权限，status=draft）
  → 编辑详情/状态（发布）
  → 配置四维数据权限（全局/部门/角色/个人，OR）
  → 单元进入检索索引（仅 published 且已授权实体可被命中）
```

### C2. AI 鉴权问答流转

```
提问者 → 登录 → 发起提问
  → 服务端校验登录态（未登录 401）
  → 智能体知识召回（向量检索 + 重排）
  → 数据权限鉴权过滤（OR 语义）
  → 仅拼装有权限内容 → LLM 生成答案
  → SSE 流式返回 + 引用来源 + 权限缺失提示
  → 记录 qa_access_logs（每轮独立日志）
```

### C3. 知识沉淀与 FAQ 闭环

```
问答日志 → 语义去重 + 频次阈值 → 候选 FAQ 推荐
  → 知识管理员审核 → 通过 → status=published → 写入 FAQ 缓存
  → 未命中/低相似度提问 → 知识缺口聚合（频次统计）
  → 缺口转知识导入任务 → 补录知识 → 回到知识维护流程
```
